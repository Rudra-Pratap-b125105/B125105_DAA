DAA LAB-5
QUESTION 4: IMPLEMENT HEAP SORT FOR N RANDOM ELEMENTS STORED IN A FILE

PROBLEM STATEMENT
Implement Heap Sort for N randomly generated elements stored in a file. Analyze the complexity of the algorithm.

APPROACH
Use a Max Heap to sort the elements in ascending order.

In a Max Heap:
Parent >= its children.

The largest element is therefore at the root. Repeatedly moving the root to the end of the unsorted portion produces ascending order.

ALGORITHM: HEAPIFY
1. Set largest = i.
2. Calculate left child = 2i + 1.
3. Calculate right child = 2i + 2.
4. Compare the current node with its children.
5. Set largest to the index of the largest value.
6. If largest is not i, swap the elements.
7. Heapify the affected subtree.

ALGORITHM: HEAP SORT
1. Build a Max Heap using bottom-up heap construction.
2. Swap the root with the last element.
3. Reduce the heap size by one.
4. Heapify the root.
5. Repeat until the heap contains one element.

FILE HANDLING
1. Read N.
2. Generate N random integers.
3. Store them in input.txt.
4. Read them from the file into an array.
5. Apply Heap Sort.
6. Display the sorted array.

PSEUDOCODE
HEAPIFY(A, N, i)
    largest <- i
    left <- 2*i + 1
    right <- 2*i + 2

    if left < N AND A[left] > A[largest]
        largest <- left

    if right < N AND A[right] > A[largest]
        largest <- right

    if largest != i
        swap A[i] and A[largest]
        HEAPIFY(A, N, largest)

HEAPSORT(A, N)
    for i <- N/2 - 1 down to 0
        HEAPIFY(A, N, i)

    for i <- N-1 down to 1
        swap A[0] and A[i]
        HEAPIFY(A, i, 0)

GENERATE_FILE(N)
    open input.txt for writing
    for i <- 0 to N-1
        generate random number
        write number to file
    close file

MAIN
    Read N
    GENERATE_FILE(N)
    Open input.txt for reading
    Read N elements into A
    Close file
    HEAPSORT(A, N)
    Display sorted array

WORKING
Example:
40 10 30 50 20 60 15

After building a Max Heap, one possible heap representation is:
60 50 30 10 20 40 15

The largest value, 60, is at the root.

Swap 60 with the last element:
15 50 30 10 20 40 | 60

Heapify the remaining portion and repeat.

Eventually:
10 15 20 30 40 50 60

Thus, the elements are sorted in ascending order.

TIME COMPLEXITY
BUILDING THE MAX HEAP
Bottom-up heap construction takes:
O(N)

This is not O(N log N).

EXTRACTING ELEMENTS
There are N-1 extraction operations.
Each extraction requires heapify:
O(log N)

Therefore:
(N-1)O(log N) = O(N log N)

TOTAL
T(N) = O(N) + O(N log N)
     = O(N log N)

BEST CASE
O(N log N)

AVERAGE CASE
O(N log N)

WORST CASE
O(N log N)

Heap Sort therefore provides an O(N log N) worst-case guarantee.

SPACE COMPLEXITY
The array is sorted in-place.

With recursive heapify, auxiliary recursion stack space is:
O(log N)

With an iterative heapify implementation, auxiliary space can be:
O(1)

FILE COMPLEXITY
Generating N elements: O(N)
Writing N elements: O(N)
Reading N elements: O(N)

These do not dominate the Heap Sort complexity.

DETAILED COMPLEXITY CALCULATION
Build heap:
O(N)

N-1 removals:
(N-1) * O(log N) = O(N log N)

Total:
O(N) + O(N log N)
= O(N log N)

COMPLEXITY SUMMARY
Generate random elements: O(N)
Write to file: O(N)
Read from file: O(N)
Build Max Heap: O(N)
Heap Sort: O(N log N)
Best case: O(N log N)
Average case: O(N log N)
Worst case: O(N log N)
Auxiliary space with recursive heapify: O(log N)
Auxiliary space with iterative heapify: O(1)

IMPORTANT VIVA POINTS
1. Why use a Max Heap for ascending order?
   The maximum element is placed at the root and can be moved to the end of the array repeatedly.

2. Complexity of building a heap?
   O(N) using bottom-up construction.

3. Complexity of Heap Sort?
   O(N log N) in best, average, and worst cases.

4. Does Heap Sort need extra array memory?
   No. It is an in-place sorting algorithm.

5. Main advantage over ordinary Quick Sort?
   Heap Sort guarantees O(N log N) worst-case time.
